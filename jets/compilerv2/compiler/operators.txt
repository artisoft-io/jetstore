# The operators of the rule engine: every name the C++ engine registers in
# create_binary_expr and create_unary_expr (jets/rete/expr_operator_factory.h).
#
# One operator a line: its arity, binary or unary, and its name, then writes_graph
# when evaluating it inserts triples into the session.
#
# Two readers keep this file and the engine in step:
#   - The compiler embeds it (jet_rule_listener_operators.go) and refuses a rule that
#     calls an operator not listed here under that arity, and a filter that calls one
#     marked writes_graph (jet_rule_listener_filter_writes.go).
#   - OperatorList in jets/rete/operator_list_test.cc fails when a name listed here
#     does not resolve in the factory, and when the factory registers a name not listed
#     here, under either arity.
#
# ADDING AN OPERATOR? Register it in jets/rete/expr_operator_factory.h and list it here
# in the same change. If it inserts into the session, mark it writes_graph; if it is an
# aggregate, list it in consequentAggregateOps too (jet_rule_listener_aggregate_salience.go).
#
# writes_graph: lookup and multi_lookup insert the looked-up rows (LookupVisitor and
# MultiLookupVisitor, jets/rete/lookup_sql_helper.cc), lookup_rand and multi_lookup_rand
# likewise, range inserts its jets:range_value triples (RangeVisitor,
# jets/rete/expr_op_others.h), and create_entity the entity's jets:key triple
# (CreateEntityVisitor, jets/rete/expr_op_resources.h). Not marked, deliberately: the
# jets:exception a failed truth test, substring_of or replace_char_of inserts on a bad
# argument, which is an error path that writes to jets:iState only; raise_exception,
# which throws and ends the rule set; and create_uuid_resource, create_resource and
# create_literal, which make a node and insert nothing.
